## 🧪 测试步骤

### 1. 基础动画测试（所有设备）

#### 测试 Topic 页面
1. 打开应用，进入首页
2. 点击任意话题
3. **观察**：页面应该从右侧 48dp 位置滑入，同时淡入
4. 点击返回按钮
5. **观察**：页面应该向右滑出 48dp，同时淡出

#### 测试 User 页面
1. 在首页或话题中点击用户头像
2. **观察**：用户页面从右侧滑入
3. 点击返回
4. **观察**：页面向右滑出

#### 测试 Login 页面
1. 退出登录（如果已登录）
2. 点击登录
3. **观察**：登录页面从右侧滑入
4. 点击返回
5. **观察**：页面向右滑出

**预期效果**：
- ✅ 动画流畅，无卡顿
- ✅ 时长约 150ms（快速但不突兀）
- ✅ 前一个页面保持可见（轻微淡出到 alpha 0.7）

### 2. 预测性返回测试（Android 13+ 设备）

#### 前置条件
1. 设备运行 Android 13 (API 33) 或更高版本
2. 在系统设置中启用预测性返回：
   - 设置 → 系统 → 开发者选项 → 预测性返回动画 → 开启

#### 测试步骤
1. 打开任意话题页面
2. 从屏幕**左边缘**向右滑动（不要松手）
3. **观察**：
   - ✅ 页面跟随手指移动（最大 56dp）
   - ✅ 背景出现半透明黑色遮罩
   - ✅ 动画完全跟手，无延迟

4. **测试取消手势**：
   - 滑动一小段距离（< 30%）后松手
   - **观察**：页面应该回弹到原位（320ms 动画）

5. **测试完成手势**：
   - 滑动较大距离（> 30%）后松手
   - **观察**：页面应该继续滑出完成返回（380ms 动画）

### 3. 边缘情况测试

#### 测试嵌套导航
1. 首页 → Topic A → Topic B → Topic C
2. 从 Topic C 返回到 Topic B
3. 再从 Topic B 返回到 Topic A
4. **观察**：每次返回动画都正常

#### 测试快速连续操作
1. 快速点击多个话题（连续打开 3-4 个）
2. 快速连续点击返回
3. **观察**：动画不应该重叠或卡顿

#### 测试旋转屏幕
1. 打开话题页面
2. 旋转屏幕
3. 点击返回
4. **观察**：动画在横屏和竖屏下都正常

### 4. 性能测试

2. 执行页面切换操作
3. **观察**：绿色条应该保持在 16ms 线以下（60 FPS）

## 🐛 常见问题排查

### 问题 1：编译错误 "Unresolved reference: TelegramStyleScaffold"

**原因**：导入语句缺失

**解决**：检查 `NativeDoNavHost.kt` 顶部是否有：
```kotlin
import io.github.baba983.nativedo.core.navigation.TelegramStyleScaffold
```

### 问题 2：预测性返回不工作

**检查清单**：
- [ ] 设备是 Android 13+
- [ ] 系统设置中已启用"预测性返回动画"
- [ ] `AndroidManifest.xml` 中有 `android:enableOnBackInvokedCallback="true"`
- [ ] `targetSdk` 设置为 34+

**临时解决**：在旧设备上，预测性返回会自动降级为普通返回按钮，功能不受影响。

### 问题 3：动画卡顿

**可能原因**：
1. 在模拟器上测试（模拟器性能较差）
2. 设备性能不足
3. 开发者选项中"动画时长缩放"设置过大

**解决**：
1. 在真机上测试
2. 检查"动画时长缩放"设置为 1x
3. 关闭其他后台应用

### 问题 4：手势返回触发太灵敏/不灵敏

**调整方案**：

在 `TelegramStyleScaffold.kt` 中修改阈值：

```kotlin
// 当前默认：30%
if (progress > 0.3f) {
    onSwipeComplete()
}

// 调整为 40%（需要更大的滑动距离）
if (progress > 0.4f) {
    onSwipeComplete()
}

// 或调整为 20%（更容易触发）
if (progress > 0.2f) {
    onSwipeComplete()
}
```
